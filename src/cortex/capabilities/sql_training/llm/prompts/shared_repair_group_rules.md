# Shared Repair Group Rules

1. The supplied errors are ontology-learnable; confirmed errors and Repair Groups are non-empty.
2. Confirm the difference, split minimal knowledge obligations, choose owner/base, then group.
3. Every confirmed error belongs to exactly one group, and every group has exactly one owner.
4. Only accepted semantic nodes are valid UPDATE bases.
5. Apply the canonical owner/reference contract without redefining it here.
6. Evaluation evidence may prove an implicit preference. Translate it into a reusable runtime condition; permanent requirements do not copy evaluation keys, Case values, or Gold-only aliases.
7. Analyze every supplied evaluator-confirmed error and preserve it in exactly one Repair Group.
8. Logical asset identity is exactly one Metric, Concept, or Generation Rule. Distinct named assets are different identities even when one depends on another; dependency between assets never makes them one identity. Merge only errors that bind the same single asset.
