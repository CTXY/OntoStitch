# 通用字段与整合原则

本模块是 **Writer** 与 **Assessment** 共用的语义标准；具体职责与输出以随后角色模块为准。规则适用于普通结果和每个完整 `alternative`。

**保留标准**：保留来源明确或其行为已经承诺的知识、条件、角色与关联；可删重复措辞，不可删事实。不重新执行 extraction 准入审计，不因来源未单独说明 `NULL`、粒度等细节新增评估义务。只有当前判断缺少具体前提时才读取 `evidence`。

## 1. 通用字段

| 字段 | 整合要求 |
| --- | --- |
| `name` / `aliases` | 选择稳定的业务名称，将其他真实同义词归入 `aliases` 并去重。不同角色或定义不能靠别名变成等价；分支独有名称留在其分支。 |
| `description` | 合并相容说明，保留必要范围与角色；不逐 case 摘抄，也不替代类型字段中的匹配、计算或行为。 |
| `tags` | 去重、归一并保留有效检索含义；相容标签可并集。标签不代替业务事实，条件性标签不广播到所有分支；无有效标签用 `[]`。 |
| `properties` | 仅使用本轮 `node_schema` 的字段和类型。不能把冲突字符串拼成数组或“X / Y”，不能新增 `parameters` 等未声明字段；历史字段无法表达时报告契约问题。 |

---

**可选字段**：不使用的 `properties` 字段应省略。字段说明中的 `default:null` 表示缺省，不代表允许显式 null；只有实际类型允许 null 时才填写。`NodeContent.description` 可以为 null。

## 2. 整合决策

| 输入关系 | 处理方式 |
| --- | --- |
| 等价或重复 | 一个完整版本，归并来源和有意义的名称；不为措辞差异制造分支。 |
| 相容互补 | 形成完整定义，保留不同角色、条件与关联。 |
| 可安全泛化 | 在现有字段中明确共同含义、参数角色与绑定；代入原输入后可还原原行为。 |
| 有依据的条件变体 | 前置条件可识别、现有字段能准确表达时条件化整合，不用 case ID 编造分界。 |
| 同范围实际不兼容 | 保留完整 `alternatives`；不投票、不跨分支拼接，也不机械求笛卡尔积。 |
| 兼容性未知 | 按需读来源；仍不确定则报告缺少前提，不默认冲突。 |
| 实为不同身份 | 给出具体反例交回 `Identity`。 |

**泛化边界**：来源必须支持参数及其取值范围；固定口径、业务阈值、计数对象、粒度、去重、`NULL` 和并列策略等既有承诺不得被抽象掉。仅有两个不同值不足以推出任意值均合法。参数含义必须写入发布内容，不能只在 `explanation` 中说明。

## 3. 内容中嵌入的关联

节点内容中已有的关系、层级或配对事实仍需保留。来源路由齐全不替代内容保留，也不证明关系语义正确；具体关系职责见角色模块。

## 4. 结果恢复模式

正常轮次使用角色指定的结果工具。仅当 controller 明确提供 `result_only_recovery.mode="plain_json"` 且 `tools_available=false` 时，直接返回符合该 schema 的完整 JSON 结果，不调用结果或读取工具；已读证据无需重复获取。
