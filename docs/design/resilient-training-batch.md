# Resilient training batches

The runner `scripts/run_resilient_training.py` consumes a prepared manifest and one input per case. One subprocess and one API key slot per active case isolates model clients, graph checkpoints, SQLite resources and logs. Physical data is read-only. Credentials are read locally from an ignored key file and are never command-line values or copied into manifests. The default endpoint is frozen in a non-secret job configuration.

`--case-workers N` optionally separates process concurrency from credential count. Independent case processes share the configured credentials round-robin; the default remains one worker per configured key slot. This changes scheduling only and retains case isolation, retry handling and semantic acceptance gates.

After an authorized endpoint replacement, `--transport-resume-plan PATH` permits explicitly listed former base URLs only when substituting that URL alone reproduces the exact native context fingerprint. The actual model uses the new endpoint; model, data, source, prompts, schema, gates and all other configuration still must match. A per-case audit records the alias, and native checkpoints and accepted evidence are not rewritten.

Each model request waits up to3600 seconds and uses8 SDK retries for retryable transport/status failures. SDK retries replay the exact request before tool execution. HTTP-level audit files count every wire attempt, including retry responses and missing responses; no auth headers are recorded. After an exhausted transient request, the worker resumes the same persistent case checkpoint with backoff, without resetting semantic rounds or accepting pending assets. Authentication and deterministic configuration failures are not silently retried as semantic failures.

Use `--streaming` for gateways that disconnect long silent nonstreaming responses. SSE bytes are flushed to the audit file as they arrive, and the completed response is reconstructed for tool/usage analysis. A narrow compatibility repair inserts the missing event delimiter only between consecutive complete JSON data lines; the original stream remains saved. The SDK receives validated assistant/tool chunks, including usage and optional reasoning. Stream buffers respect the installed SDK's actual synchronous HTTP stream class. Streaming changes transport, not ontology constraints, model-call limits or acceptance gates.

Extraction retains5 outer rounds,5 inner iterations and3 consecutive correct SQL replays. Model-call and episode limits remain disabled. Merge supports optional None for both episode-call and whole-merge budgets; finite existing defaults remain backward compatible. Only semantic rounds are bounded in this job. No domain-specific rules or source-specific corrective feedback are injected.

Source code/resources are frozen for the job. Dataset selection is exact membership of a provided train split and database, checked against the test split. Parallel extraction is followed by multi-graph merge: `--merge-batch-size` defaults to10 case graphs per operator invocation;0 supplies all remaining cases together. The existing bundle composer isolates each case's IDs, remaps references/edge metadata and preserves source-specific relation contracts before the operator jointly aligns identities, integrates content and reconciles structure. This composition makes no semantic merge decisions. Original-case to incoming IDs are recorded separately from the operator's mappings/rewrites to the result.

Batches commit serially against the accepted base, with independently audited source/reference preservation before each publication. `merge_base_state` and `merge_base_case_ids` in the manifest allow an explicitly saved accepted prefix to be reused. The complete batch plan is recorded before model execution, and input fingerprints prevent incompatible checkpoint reuse. Agent-internal local tasks do not mean one graph per operator call. Accepted intermediate merge states are saved; partial snapshots and incomplete extraction coverage are explicitly identified. Unaccepted case graphs never become accepted inputs merely to finish the batch.

Merge workspaces also retain the identity decision, content plan and unaccepted candidate patch. A saved `pending_review.stage=assess` resumes the independent assessment without repeating the writer or identity model calls. Identity read IDs are persisted with their decision. For legacy workspaces the runner recovers these IDs only from actual identity input/tool trace records matching the exact saved decision, after the input/schema/evidence fingerprint is verified; it never treats decision membership itself as read evidence.

`services.graph_merge.node_context_max_characters` controls content planning and coupled node-review packets (default110000). `request_max_characters` controls the complete node/content/relation request including messages and tool schemas (default210000). Both are character budgets, not model token limits. Operators with a larger context window can configure larger values and resume the existing workspace; coupled identities and source evidence remain intact, and semantic acceptance checks still run.

The supervisor prevents simultaneous duplicate supervisors via a local process lock. Per-case workflow writer locks and atomic JSON publication remain authoritative. A process-level coding failure is surfaced as needs_attention rather than silently skipping it. The same supervisor can restart after the prior workers have stopped; completed accepted cases and merge steps are reused.

The supervisor also watches total unanswered HTTP time: after3660 seconds without a complete response, it restarts the affected worker from its checkpoint. This covers connections whose keepalives continually reset socket-idle timeouts. Each stale request is recovered once; answered requests are not restarted. Surviving workers are adopted on supervisor restart, and completed or zombie adopted processes release their slots.

For serial merge, run the same CLI with `--mode watch` alongside the supervisor. A separate process can interrupt a blocked synchronous request after the same3660-second deadline and restart the supervisor from its persisted merge workspace. A file lock permits one watcher only. It verifies the process identity, ignores historical request files from before the current supervisor started, and leaves deterministic `needs_attention` failures visible. It changes neither semantic budgets nor acceptance criteria.

After a merge transport deadline, recovery rotates to the next configured key slot while preserving the endpoint/model and checkpoints. The slot number is logged; credentials are not. The initial merge still uses slot0 unless explicitly configured otherwise.

An explicit data-review hold is preserved across worker failure. Contradictory question/SQL inputs require a recorded data-owner resolution; they are not repaired by inventing mappings. Held or unaccepted cases are excluded from publication, and final coverage must report those exclusions.
