# 数据库本体资产契约

契约版本：database_ontology_assets_v73_case_semantics

本契约定义语义资产的含义及图编写要求。运行时 schema 规定准确的字段形状；阶段指令规定证据与交付要求。

## Event 契约

Event 表达业务发生类型，不是某一条记录或当前状态。只有证据共同标明发生什么、参与对象及其角色，以及相关的发生时间或地点时才创建 Event。单独一个事件词、时间戳、状态值或 JOIN 都不够。只保留有依据的结构；不要编造工作流、生命周期、方向、阶段或实例粒度。参与者的记录地点/当前地点不能证明历史事件发生地点；应解释查询范围，不断言无依据的发生地理位置。

- 必须有非空 description，解释发生什么，以及参与者与发生上下文之间有依据的关系。这些细节必须关联到同一事件，不能仅因为它们出现在同一个 Question 中就拼接。
- `targets` 使用与 Concept 相同的匹配组格式；当到已绑定 Concept 的显式关系足以建立事件结构时，可以为空。可选 `target_expressions` 保留必要的完整条件，不保存请求当前的日期筛选。
- 生成具体角色关系，例如有依据的发送者/接收者连接，而不是对每种角色都使用未加区分的 has_participant。每条边都需要具体解释；不增加 role 或 qualifier 字段。
- 不要从键、时间戳或 JOIN 推断一行一个事件、可计数性、顺序、因果、必需参与或完整历史。

Event targets 如果提供，应标识有依据的物理匹配组；不要把孤立时间戳、标识符或非 NULL 测试伪装成完整发生定义。一个有依据的 Event 也可以通过显式关联、已绑定的参与者与时间/地点 Concept 锚定。其 description 与保存的关系必须建立实际事件结构；空 target 列表本身绝不构成创建空壳 Event 或执行事件计数的理由。
