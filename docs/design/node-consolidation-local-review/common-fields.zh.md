# 通用字段与整合决策规范

本模块为 **Writer** 与 **Assessment** 共用的语义标准，不授予读写权限；本轮职责与唯一输出以角色模块为准。规则同时约束普通结果和每个完整 `alternative`；末尾唯一的节点类型 guidance 决定 `properties` 如何整合。

保留输入明确写出或其行为已承诺的语义；未说明细节不得编造，也不因未单独描述 `NULL`、粒度等细节而判定丢失。仅在当前比较确实依赖该前提时按需读取 `evidence`，不回审所有已接受来源。

## 1. 核心字段填写规则
- **`name`**：选择同一身份最清楚、稳定的代表名称，不用物理 ID、case ID 或多名称拼接代替业务名称。
- **`aliases`**：保留确实指向同一对象的有意义名称、缩写或同义表述并去重；名称不同但含义一致通常无需 `alternatives`。分支独有名称保留在对应分支，不将另一分支有争议名称无条件设为同义词。
- **身份与分支边界**：名称差异涉及不同角色或定义时，不可仅靠 `aliases` 宣称等价；不同身份交回 `Identity`，同一身份的不兼容版本保留 `alternatives`。例如“学校”“School”指同一实体可互为名称/别名，但“学校”与“学校名称”未必自动同义。
- **`description`**：用连贯、精确的业务说明表达整合结果，保留有区分作用的角色、范围与条件；删除重复句子，不删除事实，不逐个 case 摘抄，不使用“采用多数来源”“必要时酌情选择”等模糊表述。
- **职责分工**：`definition`、`pattern`、`condition`、`action` 等类型字段仍按类型要求填写，`description` 不替代可执行匹配、公式或规则行为；避免把所有细节重复抄入 `description` 和类型字段，简要说明业务含义、由具体字段承接定义/计算/行为，且各完整分支须能独立理解。
- **`tags`**：字符串列表，用于分类或检索，不是业务定义、适用条件或公式存储位置。去重并合并相容且有信息量的标签，近义词可统一用词（无需逐字保留全部原标签）。泛化标签不能替代具体事实（如已有“住院”“门诊”，统一为“就诊”不代表保留二者范围与差异，事实须留在类型字段或分支中）；条件性标签不可无条件加到所有分支；无须保留标签时填 `[]`，不凑数。
- **其他 `properties`**：仅填写本轮 `node_schema` 声明的字段并保持声明类型（字符串不因多值变列表，对象不退化为自由文本）。可兼容合并的字段按语义整合，不把冲突值硬拼成数组或“X / Y”，也不因重名直接覆盖一方；schema 未列出的新字段不承担契约（缺少 `parameters`、`unit`、`grain` 等字段时，必要含义保留在已有说明字段中）；遇到本轮 schema 无法表达的历史字段应报告输入/契约问题，不无声丢弃或盲目改名试错。

## 2. 整合决策矩阵

| 输入关系 | 整合方式 | 禁止做法 |
| --- | --- | --- |
| 等价、重复 | 保留一个完整版本，归并来源、别名和有效关系 | 保留多个仅措辞不同的 `alternatives` |
| 相容互补 | 合成完整定义，保留各自角色、条件与关联 | 把不同角色压成模糊的“相关字段” |
| 可安全泛化 | 在现有字段表达共同规则，并保留参数角色、边界与原实例行为 | 用宽泛说明代替可执行内容 |
| 有证据区分的条件变体 | 条件可在现有字段明确表达且消费者可用时，合成完整条件化定义 | 用 source/case ID 作业务分界 |
| 同一范围下不兼容 | 保留完整 `alternatives`、差异点及各自来源/关系范围 | 投票、拼接分支、编造互斥条件 |
| 证据不足，无法判断是否相容 | 按需读对应 `evidence`；仍无法判断则报告缺少的具体前提 | 把“不知道”直接编译成“已证实冲突” |
| 实际属于不同身份 | 给出具体反例交回 `Identity` | 强行塞进同一节点的 `alternatives` |

## 3. `generalize` 接受条件
泛化须同时满足：
1. 各输入属于本计划同一身份，且核心含义或生成决策一致。
2. 明确不变量与原材料支持的可变参数，说明参数的业务角色、取值前提和绑定来源。
3. 用原输入参数回填可还原其必要行为、范围、计算与关系，不遗漏任一方义务。
4. 保留不可变语义：计数对象、粒度、去重、`NULL`、并列名次、单位、固定业务阈值等，不得作为偶然参数删除。
5. 泛化可在现有字段和消费者能力内表达，且在发布内容中说明参数用法，不能仅写在 `explanation` 中。

Writer 将必要取舍写入现有内容与 `explanation`；Assessment 按 `Review` 格式输出问题与依据，不新增 `explanation` 字段。具体可泛化边界以本轮唯一的节点类型 guidance 为准。
