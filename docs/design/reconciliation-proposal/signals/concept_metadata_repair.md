# concept_metadata_repair：Concept 组合说明义务

## 触发与理想状态
- **触发义务**：metadata 引用退役/缺失边，去重后不足两条，谓词/方向/分支不相容，或变更可能丢失组合知识时触发明确义务。
- **健康与保义边界**：合法组满足共同契约，且原顺序、配对、覆盖等含义仍成立；仅 ID 变化、映射已正确时可不再编辑。删组消除格式错误不代表保义。

## 核查材料与示例
- **完整新旧材料**：读 before/candidate 的完整相关 Concept metadata、每个旧成员边/当前后继及映射、相关分支和实际消费者。
- **按需补齐**：仅补显式引用的入边；归档边/映射由 controller 提供，不用 read_nodes 读边 ID。
- **合法修复示例**：Route 的先 A 后 B 说明保留，只同步成员边 ID。
- **错误示例**：两边并为一边后直接删组说明；造假边、重复同一 ID 凑两条；把互斥分支的边拼为共同顺序。

## Writer 判断与调整步骤
1. **还原组合命题**：还原原组命题，沿真实映射解析每个成员，区分重复措辞与实质组合知识。
2. **保留或调整**：合法且保义时 keep；否则修订引用/范围或有据等价承接，不能只修 ID 而改变组合含义。
3. **不足两条时的处理**：只剩一条有效边时，须证明合法内容已承接原组知识才撤组；无法表达则记录能力/前提缺口，不删除知识。
4. **类型与身份边界**：不创建独立 RelationGroup，不把 Concept metadata 写入其他类型；身份问题移交 Identity。

## Assessment 核查要点
- **事实核验**：逐组比较原命题、完整新旧成员、相邻性、谓词/方向/分支、来源及消费者。
- **保义与通过边界**：不能只查数组长度或说明非空；全部组合知识有合法保留，才可关闭义务。
