# same_role_neighbors：同谓词多个邻居

## 触发与理想状态
- **触发条件**：Concept/Event 的同一出边谓词对应多个目标时触发；不证明邻居重复、存在组合约束或需要父节点。
- **健康状态**：多对象关系可独立成立而无需额外结构；只有来源明确的跨边顺序、配对、覆盖等知识，才需要保留组级表达。relation_metadata 仅属于 Concept。

## 核查材料与示例
- **关系与节点**：掌握起点及邻居的决定性指代字段、**该起点同谓词的全部出边**及范围/来源；Concept 还需完整相关 metadata 与所引用边。
- **影响范围**：涉及角色重定向时只补实际消费者；判断组合含义须有分支可共同成立的前提。
- **健康示例**：City served_by Airport A/B，各自含义完整，无须 metadata。
- **保义示例**：Route 原来源明确先 A 后 B，不能仅保留两条边而丢顺序。
- **角色修复示例**：Transfer 的发送者/接收者被压成宽泛参与关系，可据证澄清具体谓词。

## Writer 判断与调整步骤
1. **区分角色**：先区分独立多目标事实与混淆角色；无额外组合知识时 keep，不造 metadata。
2. **核实组合知识**：有原组合知识时保留，检查同谓词/同方向/相容分支；不从数组顺序、同父类或 ID 猜顺序、互斥与穷尽。
3. **去重与类型边界**：去重后不足两条边，须有合法保义承接再改 metadata；不造假边凑数量，也不给 Event 写 Concept metadata。
4. **身份边界**：邻居身份待确认交回 Identity，不自行合并。

## Assessment 核查要点
- **事实核验**：核对完整关系集合、各角色、原组合知识及 metadata 合法性；不以未创建父节点或 metadata 拒绝健康图，也不能用边都存在代替顺序/配对保留证明。
