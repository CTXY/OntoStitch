# binding_contest：直接物理绑定竞争

## 触发与理想状态
- **触发条件**：多个不同 Concept 直接 `grounded_on` 同一物理 ID 时触发；不证明它们同一身份，也不决定保留谁。
- **现行政策**：当前项目是全局单 Concept 直接绑定政策，不按 alternatives 豁免；Metric 物理输入不在竞争集合内。
- **健康与例外状态**：不同 Concept 可保留重合 targets、各自身份及有据业务关系；targets 不要求全部直接 grounding。只有旧重复边时可无需修改。

## 核查材料与示例
- **绑定与节点**：取得物理端点身份、全部竞争 Concept 的定义/完整匹配组及相关分支，**该端点全部 Concept grounded_on 入边**与完整性声明。
- **必要影响范围**：DimensionValue 还需核实 Column/value_of；只补读取决于绑定角色的业务关系、被改边 metadata 及消费者。证据用于角色判断，不计票。
- **健康示例**：School 与 SchoolName 都匹配名称列，只有 SchoolName 直接绑定，其他知识仍完整。
- **错误示例**：用两条边属于不同分支作为竞争豁免；为减少绑定而删另一个 Concept 的有效 targets。

## Writer 判断与调整步骤
1. **确认现状**：在当前图核实竞争，而非把归档副本计为活节点。
2. **判定表示角色**：比较实际表示角色；选择有据直接绑定，其他有效匹配与知识保留，需要业务关系时只补有据的具体关系。
3. **修复与复核**：退役/调整边后复核完整竞争集合、知识后继与消费者；不能预设最简单、最早或来源最多者获胜，也不靠强设 is_a 消除竞争。
4. **缺前提与身份边界**：同义身份待确认记 needs_identity；无保义选择依据记 needs_context，不能静默放宽政策。

## Assessment 核查要点
- **事实核验**：以完整物理目标入边集合确认竞争已关闭，检查全部原匹配组、角色、条件、消费者与来源后继。
- **保义与通过边界**：无竞争可接受不修改；不能要求恢复非法竞争边，也不能以结构通过掩盖匹配知识丢失。
