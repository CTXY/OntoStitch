# metric_direct_inputs：公式直接输入义务

## 触发与理想状态
- **触发义务**：公式 refs 与某有效分支的直接 depends_on/grounded_on 不一致时产生明确义务，附 expected/missing/stale；必须有关闭依据，不是可忽略提示。
- **健康与保义边界**：每个分支的真实直接输入集合与 refs 一致，重复引用同一操作数不必重复建边。新公式也属待核查内容，不能反过来证明旧知识无效。

## 核查材料与示例
- **完整公式与关系**：读完整当前/before 公式与相关分支、真实映射、操作数类型，以及该 Metric 的**全部 depends_on/grounded_on 出边**及范围/来源。
- **历史与证据**：旧内容不在 before 时精确读取授权 source；粒度/口径有疑问再读 Question/Gold SQL。历史内容与当前候选分开。
- **合法同步示例**：X/Y 已确认同一身份，公式和直接边统一映射并保留来源。
- **错误示例**：新公式只选 C1 就删仍有独立含义的 C2 依赖；用 M→X→Y 替代公式要求的 M→Y。

## Writer 判断与调整步骤
1. **逐分支比较**：逐分支比较完整 refs 与实际集合，区分语义 depends_on 和物理 grounded_on，逐项解释 missing/stale。
2. **修复与保义**：可补缺边、修正有据的端点/类型/范围或归并严格重复；旧依赖仍有有效含义时提供真实保义后继。
3. **内容与身份边界**：公式本身失真交回节点内容，操作数身份待确认交回 Identity；不改计算迎合校验，不丢 DISTINCT/NULL/粒度与计算顺序。
4. **无需新改的条件**：已由先前操作关闭时说明实际结果，不因旧 ID 消失就认定完成。

## Assessment 核查要点
- **事实核验**：比较原计算知识、真实候选公式、逐分支完整直接边及来源后继。
- **保义与通过边界**：结构一致且旧知识均有交代才关闭义务；仅有新 refs、编译通过或旧 ID 消失均不足以证明保义。
