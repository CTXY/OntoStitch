# node_relation_followup：节点阶段关系移交

## 触发与理想状态
- **触发义务**：节点阶段/controller 提供稳定义务 ID、原边、problem、required_outcome 与版本映射；这是必须闭合的明确义务。
- **健康与保义边界**：原关系或真实后继完整满足要求时可不再编辑；节点阶段通过、旧 ID 退役或旧诊断未出现都不单独证明完成。

## 核查材料与示例
- **原要求与后继**：掌握完整原要求、版本绑定、旧记录及当前后继；关系范围以该义务实际覆盖对象为准，补读必要节点字段与来源。
- **历史与来源**：已退役节点用准确授权 source 快照读，原边/映射由 controller 提供；当前路由仍使用 before 的真实来源单元。
- **已闭合示例**：E2→E1 的真实退役映射下，E1 保留原角色、范围及来源，消费者仍兼容。
- **未闭合示例**：仅因 E2 不在候选或节点已通过，就清空关系待办。

## Writer 判断与调整步骤
1. **还原义务**：按原任务/版本还原 required_outcome，沿真实映射查当前表示。
2. **定位问题类型**：区分已完成机械事项、仍需关系修复及应交回的内容/身份问题；只处理本义务耦合范围。
3. **保留或修复**：以实际结果作 keep 或最小保义修复；取得不到决定性前提时明确未完成，不为清空队列编造后继。

## Assessment 核查要点
- **事实核验**：每项义务覆盖原要求、当前后继、角色/范围/来源及消费者，keep/no-op 同样独立核查；旧 issue 明确复核。
- **保义与通过边界**：未闭合移交不能当最终成功，节点已通过与机械门禁均不能替代关系保义判断。
