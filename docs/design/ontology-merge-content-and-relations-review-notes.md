# Ontology Merge 设计审查记录

日期：2026-11-16。对应 [修订后的完整设计](ontology-merge-content-and-relations-review.md)。

## 审查范围与结论

三个 subagent 分别审查节点内容与冲突保留、Reconciliation 与重构边界、执行流程与成本复杂度。各自结合管理员、loan-date 和 card_games 分析，修订后再次复核，均未发现剩余阻断性设计问题。

本轮是文档一致性、案例推演和既有产物核对；未修改运行时代码或 prompt，未启动新的模型实验。通过不代表实际图质量或成本已验证。

## 采纳的修改

| 发现 | 修订 |
| --- | --- |
| Concept 规则偏重 targets 合并，遗漏相同 targets 的不同解读 | 明确 definition、时间含义和表示角色也可能竞争；新增 loan-date 完整例子 |
| “同范围冲突”容易漏掉部分重叠 | 改为适用范围有重叠且重叠部分不相容；不要求条件文本相同 |
| “未规定即可补充”容易只看 description | 联合完整公式、action、pattern 和定义判断，保留各项原作用域 |
| 单项内容都保留，仍可能丢掉关联 | 保留输入明确的配对、依赖和共同条件，禁止任意组合分支 |
| 受信任节点与可修改旧边的边界不明确 | 节点知识作为前提；纠正边需指出具体不一致，不能重写节点迎合偏好结构 |
| 冲突 owner 公共字段可能为空，轻量输入易误读 | 展示当前关系所需的分支含义、条件和生效边，不默认复制完整分支内容 |
| 换节点或 alternative ID 可能让专属边变成公共边 | 优先保留 ID；必须替换时明确分支后继并同步迁移范围和来源 |
| 节点重构可能再次触发输入真实性审计 | 区分保义命名/引用调整与实质重构；继承知识不因换 ID 重新认证 |
| 局部拆分与推翻 identity 的出口混淆 | 本地保义重构不推翻已确认分组；反例走当前支持的重建或失败出口，不承诺自动历史回滚 |
| 可选归纳在正文与 prompt 中条件不一致 | 同时容许必要修复与有明确组织价值的可选归纳；未做可选优化不拒绝 |
| 流程图可能被读成每批内容后重跑 Reconciliation | 补充节点批次循环，完成后进入关系阶段 |
| no-op 可能混同分支、来源语义变化 | 明确纯机械来源并集与分支重分配、来源转移的区别；不增加所有来源更新的模型评估 |

已将相关边界同步到四个 Agent 的 prompt 草案，避免正文已修而运行时拟用文本仍矛盾。

## 三组案例的审查结果

| 案例 | 原有风险 | 修订后应有行为 |
| --- | --- | --- |
| 管理员 | targets 并集被误读为全部 SELECT；属性重接时丢失姓名/邮箱配对或槽位选择冲突 | Concept 保留联合匹配组，Rule 保留选择分支；关系只修正真实邮箱主体，配对、条件与来源不变 |
| loan-date | 相同字段使两种解读被中性描述覆盖，或公共 definition 为空被判缺失 | 在身份已确认且解释竞争时保留申请/批准完整分支；首屏呈现相关分支含义；关系不得无条件混用两种解释 |
| card_games | 根据 schema 再审输入基数；只保留更合理的 JOIN；用旧边文本重复拒绝已修候选 | 保留输入基数与完整 JOIN 分支；修复文本 ID 而不误改实际端点；仅评估当前候选 |

loan-date 核对了已有 `financial_final/after.json` 的普通描述和 `financial_feedback/after.json` 的完整冲突表示。card_games 核对了 `card_uniform/agents.jsonl` 中的 JOIN 分支反馈和旧 ID 反馈。这些是设计分析依据，不是新版测试结果。

## 没有增加的复杂度

不新增 Agent、节点类型、通用分支世界、逐句知识账本、全图组合审计、固定案例规则或额外审批。保留已有部分更新、完整分支、来源映射和局部事务能力；类型规则按需提供一次。

后续实现仍应使用固定输入真实对照，分别报告语义保留、完整分支与来源、调用次数、工具读取、重试和 token 成本；静态审查不能代替这些验证。
